# t03. Больше своих соседей

**Уровень:** лёгкая · **Статус:** решена
**Ссылка:** _добавить URL задачи_

## Своими словами

В одной строке через пробел дан список чисел. Посчитать, сколько в нём элементов,
строго больших обоих своих соседей, и вывести это количество.

Крайние элементы не считаются: у первого и последнего нет **двух** соседей.
Ограничения: 1 с, 64 МБ.

## Подход

Идём по индексам от `1` до `size - 2` и проверяем `a[i] > a[i-1] && a[i] > a[i+1]`.
Сравнение строгое, поэтому плато `1 5 5 1` даёт `0`.

Списки длиной 0, 1 и 2 обрабатываются сами собой — цикл просто не выполняется.

## Что можно улучшить

Хранить весь ввод не нужно: на каждом шаге используются только три соседние
позиции, всё прочитанное раньше не понадобится. Достаточно трёх переменных,
сдвигаемых по мере чтения токенов — память O(1) вместо O(n).

Это не косметика: при лимите 64 МБ `ArrayList<Long>` стоит порядка 24–28 байт
на число (объект в куче + ссылка на него в массиве) вместо 8 байт у `long[]`.
На нескольких миллионах чисел лимит кончится.

## Грабли

- **`writer.write(int)` пишет символ, а не число.** Перегрузка `write(int c)`
  трактует аргумент как код символа: `write(2)` выведет управляющий `STX`,
  молча и без ошибки. Поэтому число оборачивают в строку —
  `String.valueOf(result)`.
- **`==` на `Long` сравнивает ссылки, а не значения.** Для чисел от −128 до 127
  Java кэширует объекты, и `==` там обманчиво «работает», а дальше ломается.
  К `>`, `<`, `>=` это не относится — они распаковывают объекты в примитивы.
- При полностью пустом вводе (EOF) `readLine()` вернёт `null` и `StringTokenizer`
  бросит NPE. На проверяющей системе такого ввода не бывает.

## Чему научилась

- Прежде чем складывать вход в коллекцию — проверить, нужен ли он целиком.
- Боксинг в Java не бесплатный: `ArrayList<Long>` ≠ `long[]` ни по памяти,
  ни по скорости.
