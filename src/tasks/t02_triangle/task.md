# t02. Треугольник

**Уровень:** лёгкая · **Статус:** решена
**Ссылка:** _добавить URL задачи_

## Своими словами

Даны три натуральных числа, каждое на своей строке. Определить, можно ли построить
треугольник с такими сторонами: вывести `YES` или `NO`.

Важная деталь условия: треугольник определён как три точки, **не лежащие на одной
прямой**. Значит вырожденный случай (одна сторона в точности равна сумме двух других)
— это `NO`, а неравенства строгие.

Верхняя граница чисел в условии не задана. Ограничения: 1 с, 64 МБ.

## Подход

Неравенство треугольника: каждая сторона меньше суммы двух других.

```
a < b + c  &&  b < a + c  &&  c < a + b
```

## Грабли

- **Переполнение `int` в сумме.** Первая версия хранила стороны в `int`, и на входе
  `1, 2147483647, 2147483647` выражение `b + c` заворачивалось в −2. Проверка
  `1 < -2` давала `false` и ответ `NO` вместо `YES`. Исключения при этом
  не возникает — программа молча считает неверно. Тесты CodeRun этот случай
  не покрывают, решение зачли с багом.
  Лечится хранением сторон в `long`: сумма считается в 64-битной арифметике.
- **`&` вместо `&&`.** На `boolean` одиночный `&` работает, но вычисляет обе части
  всегда, без сокращения. В связке вроде `s != null & s.length() > 0` это даёт NPE.
- Остаточное ограничение: парсинг идёт через `Integer.parseInt`, поэтому само
  число больше 2·10⁹ на входе всё ещё уронит программу. Для этой задачи сошло.

## Чему научилась

- Переполнение целых в Java тихое — его ловят рассуждением об ограничениях,
  а не отладкой по факту.
- `&&` — по умолчанию; `&` — только для битовых операций.
