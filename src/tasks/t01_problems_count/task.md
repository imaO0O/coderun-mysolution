## Своими словами

В первой строке через пробел даны два целых числа. Нужно вывести их сумму.

Ограничения: каждое число от 0 до 2·10¹⁸. Время — 1 с, память — 64 МБ.

## Подход

Читаем строку целиком, режем на токены, складываем.

Ключевой момент — выбор типа. Максимальная сумма по условию: 2·10¹⁸ + 2·10¹⁸ = **4·10¹⁸**.
Максимум `long` — 9,22·10¹⁸, то есть запас больше двукратного. Значит, достаточно `long`,
а `BigInteger` избыточен.

В этом файле лежит первая зачтённая версия — на `BigInteger`. Оставлена как есть,
для истории. Версия на `long` — рядом (см. ниже, если добавлена).

## Грабли

- `int` не подходит принципиально: его максимум 2 147 483 647 ≈ 2,1·10⁹, то есть
  примерно в миллиард раз меньше входных данных.
- `Integer.parseInt` на числе вне диапазона `int` бросает `NumberFormatException`
  с таким же текстом, как на мусорной строке вроде `"abc"`. Из-за этого кажется,
  что проблема в разборе строки, а не в типе.
- Переполнение `long` при сложении, в отличие от этого, **не бросает ничего** —
  число молча заворачивается по кругу и сумма может стать отрицательной.
  Поэтому максимум по условию считают заранее, а не ловят по факту.

## Чему научилась

- `BufferedReader` + `StringTokenizer` вместо `Scanner` — стандартная связка
  для чтения на скорость.
- `IOException` — checked exception: либо `try/catch`, либо `throws` в сигнатуре.
- Тип выбирается по блоку «Ограничения» в условии, до написания кода.
